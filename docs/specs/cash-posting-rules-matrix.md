# Cash Posting Rules Matrix (v1)

This matrix defines deterministic journal behavior for cash transaction types.

## General Rules

1. Register account is always the configured account of `cash_registers.account_id`.
2. Transaction amount is positive (`amount > 0`).
3. Cash transaction currency must equal register currency.
4. Journal source type for cash posting is `CASH`.
5. Posting requires period `OPEN`.

## Matrix

| Txn Type | Debit | Credit | Notes |
|---|---|---|---|
| `RECEIPT` | Register Cash | Counter Account | Cash inflow (collection) |
| `PAYOUT` | Counter Account | Register Cash | Cash outflow (payment) |
| `DEPOSIT_TO_BANK` | Bank / Cash In Transit | Register Cash | Deposit from register |
| `WITHDRAWAL_FROM_BANK` | Register Cash | Bank / Cash In Transit | Withdrawal to register |
| `TRANSFER_OUT` | Cash In Transit | Source Register Cash | Sender side of register-to-register transfer |
| `TRANSFER_IN` | Destination Register Cash | Cash In Transit | Receiver side of transfer |
| `VARIANCE` (short) | Cash Short Loss | Register Cash | Counted < expected |
| `VARIANCE` (over) | Register Cash | Cash Over Gain | Counted > expected |
| `OPENING_FLOAT` | Register Cash | Opening Float Offset | Optional operational opening entry |
| `CLOSING_ADJUSTMENT` | Depends on reason | Depends on reason | Restricted and audited |

## Validation Rules by Type

1. `TRANSFER_OUT` requires target register reference.
2. `TRANSFER_IN` requires source register reference or transfer reference.
3. `DEPOSIT_TO_BANK` and `WITHDRAWAL_FROM_BANK` require bank account/counter account.
4. `VARIANCE` can only be system-generated by session close workflow.

## Immutability

1. `POSTED` entries cannot be edited.
2. Corrections are made with `REVERSED` + new transaction entry.
